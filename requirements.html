وثيقة تحليل المتطلبات الفنية (SRS)

مشروع تطبيق: سند (Sanad)

إعداد المحلل: أحمد عبد الكريم

1. هيكلية المهام (Tasks Logic)
العملية الوصف الوظيفي الربط البرمجي
Create Task إنشاء "قالب" المهمة العام يُخزن في جدول المهام الرئيسي
Create Task Assignment إسناد مهمة معينة لمتطوع محدد يربط بين الـ Volunteer ID والـ Task ID

منطق شاشة الهوم: يتم ربط الـ Task Assignment الخاص بـ ID المتطوع بـ Task Today من خلال فلترة التاريخ الحالي.

2. تكامل الـ APIs والتقارير
  • الربط: ربط API الـ Reports بـ API الـ Campaigns (كل تقرير ينتمي لحملة).
  • الصلاحيات: (-) السماح للمستخدم العادي بتعديل تقريره الخاص من خلال الـ API.

نقاط النهاية المطلوبة (Endpoints):

GET /api/reports/{id} // Get report with ID
PUT /api/reports/{id} // Update report
GET /api/sos/{id} // List SOS request by ID
PATCH /api/sos/{id} // Update SOS request status
POST /api/ai/chatbot // Chatbot API Integration
3. نظام النقاط والترقية (Gamification)

(+) لوحة المتصدرين: يتم ترتيب المتطوعين تنازلياً (من الأعلى إلى الأقل) بناءً على إجمالي النقاط.

نظام الألقاب (بناءً على الساعات والمهام):

اللقب شرط الاستحقاق المستوى
منقذ المستوى الترحيبي (أقل مرتبة) 1
بطل توعية تحقيق عدد ساعات ومهام متوسط 2
منفذ تحقيق أعلى معدل ساعات وإنجاز مهام 3
4. متطلبات واجهة المستخدم (UI/UX)
(-) حذف: لا يوجد صفحة مستقلة باسم (page reports done list reports).
(+) إضافة: شاشة لوحة المتصدرين (Leaderboard) مع عرض الألقاب بجانب الأسماء.
